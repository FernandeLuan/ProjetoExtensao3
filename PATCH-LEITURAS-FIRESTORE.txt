SR NK — PATCH DE LEITURAS FIRESTORE v2.1.4

CAUSA PRINCIPAL ENCONTRADA
==========================
Havia um ciclo real entre Equipe e Atendimento retroativo:

1. listarMembrosEquipe() fazia uma leitura no Firestore;
2. a função gravava o resultado no state.equipe;
3. state.equipe disparava o listener do retroativo;
4. o listener chamava prepararProfissionais();
5. prepararProfissionais() chamava listarMembrosEquipe() novamente;
6. voltava ao passo 1.

Isso podia repetir leituras de membros continuamente enquanto a aplicação estava aberta.

O QUE ESTE PATCH MUDA
=====================
- Remove o ciclo Equipe -> state -> Retroativo -> Equipe.
- O app não busca mais atendimentos na inicialização.
- Painel só busca atendimentos quando o Painel é aberto.
- Histórico só busca quando o Histórico é aberto ou a data é alterada.
- Relatório só busca quando a tela Relatório é aberta / período ou visão muda.
- Despesas só busca quando a tela Despesas é aberta / mês muda.
- Equipe só busca quando a tela Equipe, Histórico/Relatório administrativo ou Configurações precisam da lista.
- Minha Conta só consulta os dados completos quando a tela Minha Conta é aberta.
- Consultas iguais em andamento são compartilhadas, evitando duplicação simultânea.
- Cache de atendimentos/despesas: 2 minutos.
- Cache da equipe: 5 minutos.
- Um período já carregado pode atender uma consulta menor sem nova leitura. Ex.: Painel carrega 7 dias; Histórico de hoje pode reutilizar esses dados.
- Registrar atendimento não faz uma nova leitura só para mostrar o registro recém-criado.
- Editar atendimento atualiza o state local e invalida o cache para a próxima consulta.
- Painel e Histórico deixam de reconstruir o DOM quando estão escondidos.
- Todos os módulos do dashboard foram alinhados para v=7.4. O Relatório tinha imports v=7.1 misturados com v=7.3, o que podia criar instâncias separadas dos módulos ES.

DIAGNÓSTICO NO CONSOLE
======================
O patch cria:

window.__SRNK_LEITURAS__

No Console do navegador você pode digitar:

__SRNK_LEITURAS__

Ele mostra, durante a sessão, quantas consultas o código disparou e quantos documentos retornaram por origem.
Esse contador é diagnóstico do app e não substitui a métrica oficial de faturamento do Firebase.

TESTE RECOMENDADO QUANDO A COTA VOLTAR
======================================
1. Abra o app e fique na tela Início por 1 minuto.
   - Não deve existir crescimento contínuo de consultas.
2. Abra o Console e rode: __SRNK_LEITURAS__
3. Abra Painel uma vez.
4. Abra Histórico uma vez.
5. Volte ao Painel e Histórico dentro de 2 minutos.
   - As mesmas consultas devem ser reaproveitadas quando o cache cobrir o período.
6. Abra Equipe e deixe parado.
   - A consulta de equipe deve acontecer uma vez, não continuamente.
7. Confira no Firebase se as leituras não começam a subir em linha reta como antes.

ARQUIVOS FIREBASE
=================
Este patch não exige novas Rules nem novos índices.
